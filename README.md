# plex

Batch video encoding, Plex media renaming, an unattended ingest from the completed-downloads directory to a holding directory, and Plex Age/Target labeling for a personal media library, with a shared configuration layer, concurrency locks, a single source of truth for subtitle language codes, and a one-time SMB mount helper for the NAS share.

├── README.md                       ← this file
├── .gitignore
├── data/                           Label pipeline CSVs (local, not committed; see Plex labels)
│   ├── plex_folders.csv            Created and kept current by stage 1: folder names plus Plex's own titles and IDs
│   └── plex_labels.csv             Generated by stage 2, read by stage 3
├── logs/                           Label pipeline logs (created on first run; not committed)
└── scripts/
    ├── config.sh                   Paths, encoder settings and the ingest settle window, sourced by media.sh
    ├── media.sh                    Run a stage: `media.sh encode|rename|ingest|release|archive [-n]`; -n previews it (nothing is written, renamed or moved); prints [DRY RUN] or [LIVE] first
    ├── ingest.sh                   Unattended stage from the completed-downloads directory to the holding directory: settle check, rename preview, real rename only when the preview is clean, then move (called by media.sh; can also be run standalone)
    ├── release.sh                  Moves held entries from the holding directory to the encoder's input directory (called by media.sh; can also be run standalone)
    ├── archive.sh                  Moves encoded files from the local archive directory to the NAS archive directory, category by category, with copy verification (called by media.sh; can also be run standalone)

## One-time setup

### Mount the NAS share

`setup_smb_mount.sh` mounts a CIFS/SMB share (for example a NAS) at a stable local path, owned by a normal user, so the pipeline scripts, which refuse to run as root, can read and write it. `archive.sh` is the stage that writes to it by default. It is the one script in this repo that must run as root: installing `cifs-utils`, writing `/etc/fstab` and mounting all need it.

```bash
cd scripts
./setup_smb_mount.sh -n -p Movies nas.local media /mnt/nas/movies    # preview; needs no root
sudo ./setup_smb_mount.sh -p Movies nas.local media /mnt/nas/movies  # do it
```

For the archive stage, mount the whole share (no `-p`) and let `NAS_ARCHIVE_DIR` add the `#archive` folder, since `setup_smb_mount.sh` refuses a `#` in a subpath:

```bash
sudo ./setup_smb_mount.sh nas.local plexmedia /mnt/nas/plexmedia
```

| Option | Meaning |
|---|---|
| `-p PATH` | Subpath within the share (default: the whole share) |
| `-u USER` | Local user who owns the mounted files (default: the user who ran `sudo`) |
| `-c FILE` | SMB credentials file (default: `/etc/samba/credentials/<share>`; root-owned, mode 600) |
| `-v VERS` | SMB protocol version (default: 3.0) |
| `-o OPTS` | Extra mount options, comma-separated, appended to the fstab line (default: none) |
| `-f` | Overwrite an existing `/etc/fstab` entry or credentials file instead of leaving it in place |
| `-n` | Dry run: print every step, change nothing |

It prompts for the SMB username and password and writes them only to the credentials file. `/etc/fstab` is backed up (timestamped) before any change, and only one line is ever appended or replaced. It needs bash 4.0+, `apt-get` (Debian/Ubuntu), `mountpoint` and `runuser`. It refuses a target user that resolves to root, and a `#` in the server, share, subpath or mount point. After mounting it confirms that the path is a mount point and writable by the target user. It takes no lock because it is a short, single provisioning run.

The label pipeline does not need this mount: it talks to Plex over its API.

### Lint

```bash
./scripts/lint.sh
```

Runs `shellcheck -x` on every `.sh` file under `scripts/` (installing shellcheck through apt first if it is missing) and a syntax check on every `.py` file (no packages needed; it writes no bytecode). Exits non-zero if any file has findings, so it can serve as a pre-commit gate later; it is not wired up as one.

## Workflow

### Pipeline

| Stage | Command | Reads | Writes |
|---|---|---|---|
| Ingest | `media.sh ingest` | `$DOWNLOADS_INPUT_DIR` (`$DOWNLOADS_BASE/Complete`) | Renames in place, then moves entries to `$UNENCODED_DIR` (`$VIDEOS_BASE/unencoded`), the holding directory |
| Release | `media.sh release` | `$UNENCODED_DIR` | `$INPUT_DIR` (`$VIDEOS_BASE/input`) |
| Encode | `media.sh encode` | `$INPUT_DIR` | `$OUTPUT_DIR` (`.tmp` files and logs), then `$ARCHIVE_DIR` (`encoded`, from `-M`) and `$BACKUP_DIR` (`backup`, the sources, from `-A`) |
| Archive | `media.sh archive` | `$ARCHIVE_DIR` | `$NAS_ARCHIVE_DIR` (`$NAS_MOUNT/#archive`), then removes the local copy |

No script moves `$BACKUP_DIR` to cold storage.

### 1. Ingest finished downloads (automatic, or on demand)

```bash
cd scripts
./media.sh ingest -n    # preview — settle check and rename preview, nothing changes
./media.sh ingest       # run it for real
```

`media.sh ingest` works on `$DOWNLOADS_INPUT_DIR` and moves the result to `$UNENCODED_DIR`. In order:

1. **Settle check.** The files must be unchanged across `$INGEST_SETTLE_SECONDS`; otherwise the run ends and the next one retries.
2. **Preview.** `rename.sh -n -x` on the whole directory. A skipped, unmatched or to-be-deleted file stops the run with exit 2 before anything changes.
3. **Rename.** `rename.sh -x` with no input attached, so a subtitle-deletion prompt is answered "no" instead of blocking the run.
4. **Move.** Each top-level entry that holds a video moves to `$UNENCODED_DIR`. An entry with no video, or whose name already exists there, stays and is listed for review.

When a step needs a decision, `$DOWNLOADS_BASE/Logs/Ingest_review.txt` says what. Fix it (rename the file, delete the leftover, clear the name in the holding directory) and the next run starts over. See [`ingest.sh`](#ingestsh) for the details.

To run it on a timer:

```bash
cd scripts
./install_units.sh -n   # preview the two unit files
./install_units.sh      # write them to ~/.config/systemd/user
systemctl --user daemon-reload
systemctl --user enable --now media_ingest.timer
```

The service runs `media.sh ingest` 2 minutes after the user manager starts and `-i` minutes (default 5) after each run ends. A run that exits 2 shows as a failed unit in `systemctl --user --failed`. User timers stop when the last session ends unless lingering is enabled (`sudo loginctl enable-linger "$USER"`).

To rename a directory without moving anything, run `./media.sh rename -n` and `./media.sh rename`, which target `$DOWNLOADS_INPUT_DIR` and pass `-O "$DOWNLOADS_BASE"` (where the lock and logs go, see [Concurrency lock](#concurrency-lock)). To rename any other directory, call `rename.sh` directly with an explicit target.

### 2. Release held entries

`$UNENCODED_DIR` is a holding area. Nothing leaves it on its own.

```bash
cd scripts
./media.sh release                   # list what is held
./media.sh release -n "Name (2020)"  # preview moving one entry to $INPUT_DIR
./media.sh release "Name (2020)"     # move it
./media.sh release -a                # move everything
```

Item names go after the options, and `--` ends the options. `release` never overwrites or merges a name that already exists in `$INPUT_DIR`, and it is safe while an encode runs. See [`release.sh`](#releasesh).

Ingest and release must finish before the encode: filenames must already be correct by the time the encoder builds sidecar-subtitle paths from them.

### 3. Encode a batch

```bash
cd scripts
./media.sh encode -n    # preview — review the plan, nothing is written
./media.sh encode       # run it for real
```

`media.sh encode` takes `-n` and prints `[DRY RUN]` or `[LIVE]` first. It sources `config.sh` for paths/flags and calls the real work out to `encode.sh`, targeting `$INPUT_DIR`. A run lists its input files once, at the start, so entries released into `$INPUT_DIR` while it runs wait for the next encode. Never run `media.sh encode -n` and `media.sh encode` at the same time against the same output directory — see [Concurrency lock](#concurrency-lock).

The dry run prints each file's decision, including whether an HDR source is tone-mapped to SDR (see [HEVC and HDR sources](#hevc-and-hdr-sources)), the ffmpeg command in a form that can be pasted into a shell, and each planned `-M` archive and `-A` backup move, with a warning for any destination that already exists.

To change quality, paths, or run against a different tree without editing any file:

```bash
CRF=18 PRESET=slow ./media.sh encode
VIDEOS_BASE=/mnt/scratch/Videos ./media.sh encode -n
```

### 4. Archive encoded files to the NAS (automatic, or on demand)

```bash
cd scripts
./media.sh archive -n   # preview: nothing is copied or deleted
./media.sh archive      # run it for real
```

`media.sh archive` moves the files in `$ARCHIVE_DIR` to `$NAS_ARCHIVE_DIR`, category by category, and deletes each local file only after the NAS copy is verified. It ends before any work when `$NAS_MOUNT` is not mounted. A collision, or a top-level entry that is not a category folder on the NAS, leaves the file in place and exits 2. See [`archive.sh`](#archivesh).

To run it on a timer, use the same installer with the archive stage:

```bash
cd scripts
./install_units.sh -s archive -n   # preview the two unit files
./install_units.sh -s archive      # write them to ~/.config/systemd/user
systemctl --user daemon-reload
systemctl --user enable --now media_archive.timer
```

### 5. Scan a library for subtitle risk (optional, read-only)

```bash
cd scripts
./scan_subtitle_types.sh -r "$INPUT_DIR"
```

Inventories every embedded subtitle stream under a directory, classified by whether its codec can carry a leftover ASS override tag as literal on-screen text (`subrip`/`mov_text`) or not (`ass`/`ssa`, bitmap). It takes its target directory as a plain argument and writes nothing beyond an optional `-o` report file.

### 6. Label the Plex library with Age and Target

Run this after Plex has scanned the files: labels are applied to items Plex already has, matched by folder name on disk.

```bash
cd scripts
export MAL_CLIENT_ID='...' TMDB_API_KEY='...'
export PLEX_URL='http://<nas-ip>:32400' PLEX_TOKEN='...'
./plex_labels.sh                        # all three stages, in order
./plex_labels.sh -n                     # every stage in dry-run (needs plex_labels.csv from an earlier run)
./plex_labels.sh --check-source-route   # also log whether source-work demographics agree with MAL's own
```

See [Plex labels](#plex-labels-age-and-target) for the rules, the inputs and each stage on its own.

## `config.sh`

Defines three independent variable groups: the video-library pipeline (from `VIDEOS_BASE`), the completed-downloads directory the rename and ingest stages read (from `DOWNLOADS_BASE`) and the NAS share the archive stage writes to (from `NAS_MOUNT`):

| Variable | Default | Passed to |
|---|---|---|
| `VIDEOS_BASE` | `$HOME/Videos` | Base for the five video-library directory variables below |
| `INPUT_DIR` | `$VIDEOS_BASE/input` | `encode.sh` positional arg |
| `OUTPUT_DIR` | `$VIDEOS_BASE/output` | `encode.sh` `-o` (via `ENCODER_ARGS`) |
| `ARCHIVE_DIR` | `$VIDEOS_BASE/encoded` | `encode.sh` `-M` (via `ENCODER_ARGS`); `archive.sh` source directory (positional arg) |
| `BACKUP_DIR` | `$VIDEOS_BASE/backup` | `encode.sh` `-A` (via `ENCODER_ARGS`) |
| `UNENCODED_DIR` | `$VIDEOS_BASE/unencoded` | `ingest.sh` holding directory (positional arg); `release.sh` `-S` |
| `CRF` | `20` | `encode.sh` `-c` (via `ENCODER_ARGS`) |
| `PRESET` | `slow` | `encode.sh` `-p` (via `ENCODER_ARGS`) |
| `TUNE` | empty | `encode.sh` `-T` (via `ENCODER_ARGS`, only when set) |
| `MAX_COPY_KBPS` | `8000` | `encode.sh` `-K` (via `ENCODER_ARGS`) |
| `INGEST_SETTLE_SECONDS` | `60` | `ingest.sh` `-w` |
| `DOWNLOADS_BASE` | `$HOME/Downloads` | `rename.sh` and `ingest.sh` `-O` (lock/log location only, not the target) |
| `DOWNLOADS_INPUT_DIR` | `$DOWNLOADS_BASE/Complete` | `rename.sh` and `ingest.sh` positional arg (the actual target) |
| `NAS_MOUNT` | `/mnt/nas/plexmedia` | `archive.sh` `-m` (the share's mount point) |
| `NAS_ARCHIVE_DIR` | `$NAS_MOUNT/#archive` | `archive.sh` positional arg (the destination) |
| `ARCHIVE_SETTLE_SECONDS` | `60` | `archive.sh` `-w` |

No paths or usernames are hardcoded — everything derives from `$HOME` unless overridden. `ENCODER_ARGS` is a prebuilt array (`-r -s -c "$CRF" -p "$PRESET" -K "$MAX_COPY_KBPS" -o "$OUTPUT_DIR" -M "$ARCHIVE_DIR" -A "$BACKUP_DIR"`, plus `-T "$TUNE"` when `TUNE` is set) that `media.sh encode` splices in ahead of `$INPUT_DIR`; there is no equivalent prebuilt array for rename, ingest or release, since each needs only the raw directory values passed directly. `media.sh release` and `media.sh archive` pass `-O "$OUTPUT_DIR"`, so their logs sit beside the encoder's. `NAS_MOUNT`, `CRF`, `PRESET`, `TUNE`, `MAX_COPY_KBPS`, `INGEST_SETTLE_SECONDS` and `ARCHIVE_SETTLE_SECONDS` take overrides at call time; `INGEST_SETTLE_SECONDS=0 ./media.sh ingest -n` skips the settle wait.

`config.sh` does not set the maximum output height. The encoder's `-H` flag does (default 1080), so `media.sh` always uses 1080; call `encode.sh` directly to change it.

The label scripts do not source `config.sh`. They locate their own inputs and outputs relative to themselves (`../data`, `../logs`) and take credentials from the environment (see [Plex labels](#plex-labels-age-and-target)).

## Concurrency lock

`encode.sh`, `rename.sh`, `ingest.sh`, `release.sh` and `archive.sh` each take their own exclusive, non-blocking `flock`, once the directory they work from is ready: `encode.sh` creates `OUTPUT_DIR` first, and the others resolve the target's canonical path. A dry run of `rename.sh`, `ingest.sh`, `release.sh` or `archive.sh` takes no lock and writes no log. A second run against the same directory, from any invocation path (`media.sh`, or a script called directly), exits immediately with an error instead of racing. The lock releases automatically when the process exits, including on Ctrl-C.

No script's lock (or logs) live inside the directory being processed — each routes through an operational directory instead:
- `encode.sh` locks `OUTPUT_DIR/.media.lock` and logs to `OUTPUT_DIR/Logs`, since `OUTPUT_DIR` is a working/encoding area, not a curated library.
- `rename.sh` takes an `-O DIR` flag (operational directory) for the same purpose: `media.sh rename` passes `-O "$DOWNLOADS_BASE"`, so its lock (`DOWNLOADS_BASE/.locks/<hash-of-target>.lock`) and logs (`DOWNLOADS_BASE/Logs`) stay out of the actual rename target. Since `rename.sh` can also run standalone against any target, `-O` defaults to the script's own directory when omitted.
- `ingest.sh` and `release.sh` take the same `-O DIR` flag with the same default. `media.sh ingest` passes `-O "$DOWNLOADS_BASE"` and `media.sh release` passes `-O "$OUTPUT_DIR"`. `ingest.sh` locks `DOWNLOADS_BASE/.locks/ingest_<hash-of-source>.lock`, named apart from `rename.sh`'s `<hash>.lock` for the same directory because it runs `rename.sh` as a child. `release.sh` locks `OUTPUT_DIR/.locks/release_<hash-of-input>.lock`. Neither takes `encode.sh`'s lock, since `encode.sh` lists its input files once at the start.
- `archive.sh` takes `-O DIR` with the same meaning; `media.sh archive` passes `-O "$OUTPUT_DIR"`. It locks `OUTPUT_DIR/.locks/archive_<hash-of-source>.lock`. It does not take `encode.sh`'s lock: `encode.sh -M` copies into the directory `archive.sh` reads, and the settle window keeps `archive.sh` off a file still being written.

`config.sh` and `media.sh` contain no locking logic — they're path/flag plumbing only. `encode.sh`, `rename.sh`, `ingest.sh`, `release.sh` and `archive.sh` can be run standalone, without going through `media.sh`, and are still protected.

The label scripts keep their lock files in `scripts/` instead, and remove them when a run ends:
- `plex_labels.sh` takes `.plex_labels.lock` when it runs all three stages, so only one pipeline runs at a time.
- `get_plex_labels.py` takes `.get_plex_labels_<hash>.lock`, scoped to its cache file, so a second run against the same cache exits while runs against another cache proceed.
- `apply_plex_labels.py` takes `.apply_plex_labels_<hash>.lock`, scoped to the Plex server and library selection.

## Centralized language table

`lang_table.tsv` is the single source of truth for every language code, alias, and display label used across the project — add a language once here and it's picked up everywhere. Each row has a primary 3-letter code (`code3`, ISO 639-2), a 2-letter code (`code2`, ISO 639-1, used in sidecar filenames), a display label, and a comma-separated alias list (e.g. `fra`'s alias is the bibliographic `fre`). **Pass the primary `code3` to `-l`.** Sidecar discovery looks each `-l` value up in `LANG_3TO2` and silently skips a value with no entry, and the encoder's own check only warns when a value is not 2–3 letters. Aliases are for matching a file's own language tag and for display; the lowercase label also resolves as a language name in subtitle file names; English is the supported one.

- `encode.sh` sources `lang_table.sh` for its bash-side sidecar matching (`LANG_TABLE`, `LANG_3TO2`, `LANG_LABEL_BASH`), and `probe_streams.py`, which it calls to read each file's streams, reads `lang_table.tsv` directly for embedded-track display labels (which resolve aliases).
- `rename.sh` sources `lang_table.sh` for the `LANG_ALIASES` lookup in `rename_parse.sh`, used to normalize subtitle filename language tags (e.g. `.eng.srt` → `.en.srt`, `.fre.srt` → `.fr.srt`) to the 2-letter form `encode.sh`'s sidecar matching expects.
- `video_exts.sh` defines `VIDEO_EXTS`, the one video extension list `encode.sh`, `rename.sh` and `scan_subtitle_types.sh` all read.
- `subtitle_mux.sh` does not source `lang_table.sh`: it depends on `LANG_3TO2`/`LANG_LABEL_BASH` already being loaded by whichever script sourced it.

Both `lang_table.sh` and `lang_table.tsv` resolve their own file locations relative to themselves, not the caller's working directory, so this works regardless of where a script is invoked from. `lang_table.sh` is also safe to source more than once in the same process (an include guard makes the second call a no-op).

## `encode.sh`

The core encoder is documented in full detail — every flag, the audio/subtitle decision logic, sidecar handling, and logging format — in its own header comment (`-h`). The ffmpeg argument builders for video, audio and embedded subtitle tracks are in `encode_args.sh`; the file handling, sidecars, verification, archiving and locking are in `encode.sh`. It can be run directly (bypassing `config.sh`; it still takes its own lock) for one-off jobs outside the standard `VIDEOS_BASE` layout. Run directly, its defaults are CRF 18, preset `slow` and output to `encoded` beside the script; `media.sh` overrides them through `config.sh` (22 and `fast`). It requires an ffmpeg build with the `zscale` and `tonemap` filters and exits before any work if either is missing.

### Video decisions

`MAX_HEIGHT` is the encoder's `-H` value (default 1080). `MAX_COPY_KBPS` is its `-K` value (default 8000; 0 always copies): the file's overall bitrate, container size over duration, so it includes audio and overstates the video bitrate. A file whose size or duration cannot be read is copied.

| Source | Result |
|---|---|
| h264, SDR, height ≤ `MAX_HEIGHT`, overall bitrate ≤ `MAX_COPY_KBPS` | Stream copy (colour tags are unchanged because the stream is not touched) |
| h264, SDR, height ≤ `MAX_HEIGHT`, overall bitrate > `MAX_COPY_KBPS` | Re-encoded to x264 at native height (a Blu-ray remux takes this row) |
| h264 with a PQ or HLG transfer, height ≤ `MAX_HEIGHT` | Tone-mapped to SDR, re-encoded to x264, tagged bt709 |
| h264, height > `MAX_HEIGHT` | Scaled to `MAX_HEIGHT` (width derived from the aspect ratio, even-numbered), re-encoded to x264; if PQ or HLG, scaled and then tone-mapped |
| Any other codec, SDR | Re-encoded to x264 at native or `MAX_HEIGHT` height |
| Any other codec, PQ or HLG | Tone-mapped to SDR, re-encoded to x264, tagged bt709 |

An HDR source is identified by its colour *transfer function* (`smpte2084` for PQ, `arib-std-b67` for HLG), read by `probe_streams.py`. Colour primaries are not used: they describe gamut, and BT.2020 primaries can accompany an SDR curve.

Every encoded file's video stream is probed while it is still the `.tmp` file. A file whose transfer function is still PQ or HLG is rejected: it is deleted, logged as `FAILED (HDR transfer in output)`, and never reaches `OUTPUT_DIR`. This ordering matters because `-M` copies the output to the archive and then deletes it, and `-A` moves the source to the backup directory; both run only after the probe passes. The encode can exit 0 with wrong tags, and those two steps are destructive.

### HEVC and HDR sources

**HEVC sources** are always re-encoded to x264. The script prints a warning because transcoding HEVC to x264 can produce a larger file.

**HDR sources are converted to SDR rather than carried through, and tagged explicitly, for these reasons:**

1. **libx264 copies the input's colour tags into the output header unless they are set.** The three tags (colour primaries, transfer characteristics, matrix coefficients) tell a player which gamut, brightness curve and YCbCr conversion to apply. `-pix_fmt yuv420p` changes bit depth only; it does not change the transfer curve. An HDR10 source encoded to 8-bit h264 without tone-mapping therefore yields PQ-coded pixels tagged BT.2020/PQ. Observed with ffmpeg 6.1.1: an encode without colour handling reports `color_transfer=smpte2084`, `color_primaries=bt2020`, `color_space=bt2020nc`.

2. **Roku does not list HDR10 for h264.** Roku's media specification lists HDR support for AVC (H.264) only as Dolby Vision profile 9 (`dvav.09`), with HDR10 listed under HEVC, VP9 and AV1 ([developer.roku.com/dev/docs/media](https://developer.roku.com/dev/docs/media)). Dolby Vision profile 8 is 10-bit HEVC; the 8-bit AVC profile is 9 ([Dolby Vision profiles](https://en.wikipedia.org/wiki/Dolby_Vision)). An 8-bit h264 stream tagged PQ/BT.2020, or carrying a profile 8 configuration record, matches no HDR combination Roku lists for AVC.

3. **Observed behavior on a Roku running the Plex app.** Files of that shape stop within about 0.4 s of the playback start request, before any transcode segment is requested, and play in the Plex app on Android. Rewriting only the h264 colour tags to bt709 (no re-encode) made one such file play on the Roku. The Roku-side reason for rejecting the tags is not documented in any source found. The Plex Roku client's declared decoder capabilities (from the server log) are h264 high profile, 1080p, level 4.1, which is what the encode path targets.

4. **Tone-mapping, rather than retagging, makes the tags true.** Tags describe pixels. If the pixels are PQ-coded and the tags say BT.709, a player displays them as SDR and the picture is flat or dim. The tone-map converts the pixels to BT.709 before libx264 sees them, so the explicit bt709 tags describe the actual content.

The conversion filter chain lives in one constant, `SDR_TONEMAP_CHAIN`, near the top of the script. It uses `hable` tone-mapping with `npl=100`, and was run on a synthetic PQ clip, where it produced bt709 tags; it has not been tuned on real footage, and changing it changes only the look of converted sources.

### Known limitations

- **Missing primaries or matrix tags.** A PQ source whose colour primaries and matrix tags are unspecified fails in `zscale` with `no path between colorspaces`. The file is logged `FAILED`, no output is written, and the source is untouched. Reproduced with a PQ-tagged clip that carries no primaries or matrix tag.
- **HLG.** HLG sources take the same chain; it was run with PQ input only.
- **Dolby Vision configuration record.** A source's Dolby Vision record is carried onto an encoded output by ffmpeg 6.1.1 (a libx264 output with one was observed), and no verified method strips it at encode time. The script warns when a source or an output carries one. Whether the record alone prevents Roku playback is untested.
- **Mislabelled SDR.** A source with SDR pixels wrongly tagged PQ is tone-mapped like an HDR source, because the tag is the only machine-readable signal.
- **Existing HDR-sourced outputs.** An output encoded without tone-mapping from an HDR source holds PQ-coded pixels. Re-encode it from the source; a tag rewrite makes it play but leaves the picture misdescribed.

### Subtitles

Sidecar discovery, the container-aware subtitle codec choice and external-subtitle ffmpeg arg building live in the shared `subtitle_mux.sh`. Sidecars are tag-stripped before muxing (see [Subtitle tag stripping](#subtitle-tag-stripping-strip_subtitle_tagspy)).

## `rename.sh`

Renames movie and TV-episode video and subtitle files into Plex convention. The name parsing (everything that turns a raw name into a Plex name, with no filesystem access) is in `rename_parse.sh`; the file and folder operations, collision handling, logging and locking are in `rename.sh`:

- **Movies:** `Franchise/Movie Name (YYYY) {edition-A B}/Movie Name (YYYY) {edition-A B}.ext`. Several editions in one name are joined alphabetically with Remastered last.
- **Episodes:** `Series Name (YYYY)/Season XX/Series Name - SxxEyy[ - Title].ext`. The episode title is the text after `SxxEyy`, with or without a hyphen between them, cut at the first release tag (resolution, source, codec, audio, HDR or streaming-service tag, plus upper-case language codes right before it): `Series.S01E01.Real.Title.ITA.1080p.WEB-DL.x264-GRP` gives `Series - S01E01 - Real Title`. A release group with no tag before it (`Series.S01E01.Real.Title-GRP`) stays in the title.
  - A `Series Name (YYYY)` folder that holds episodes names everything under it: each episode takes the folder's title, whatever its own file name says.
  - An `NxMM` token (`1x01`, `10x105`) or an `SxxEyy` token split by one space, dot or underscore (`S01 E01`, `S01.E01`) is read as `SxxEyy` (`S01E01`, `S10E105`) and needs no sibling files. The `NxMM` episode needs two or three digits, so `1x1` and resolutions such as `1920x1080` are left alone.
  - The season folder comes from the file name (`SxxEyy`, `NxMM`, `Season N`, or a season marker ending the title such as `Show S2`), else from the `Season NN` folder the file sits in (`Season NN - Descriptor` counts, and the descriptor is dropped), else it is season 1.
  - Files under the show folder with no episode number (extras, credits) move to `Season 00` with a cleaned name.
  - Without a show folder, the year comes from the file's name. When neither has one, the show folder is `Series Name` and you add the year to that one folder by hand.
  - A release folder that names the series in its own `(...)` group (`Native Title (Series Title) (Season 02)`) is emptied into the series folder beside it, so every season merges into one show folder.
  - A name without an `SxxEyy` token (`Episode 12`, `- 12`, `- 12 - Title`, `Show.12`) is read as an episode only when at least two videos in the same folder share the title before the number; the title after `Episode 12` is kept, and the title after `- 12 -` is dropped. A separated version suffix (`- 12 v2`) is dropped.
  - A `.5` after the number is kept as a special (`Show - 02.5` becomes `S01E02.5`).
- **Subtitles:** language tags and modifiers (`cc`/`sdh`/`forced`) are normalized against `lang_table.tsv` (loaded by `lang_table.sh`), so files renamed here match what `encode.sh`'s sidecar discovery looks for. A subtitle named only by a language word resolves through the table's label column, matched in lowercase; English (`English`, `2_English`) is the supported language.
  - **Release-folder subtitles:** a subtitle named only `<track> <language>` (`2 English.srt`, `3_English.srt`) under a show folder takes its episode from the nearest folder above it with an `SxxEyy` token and becomes `Series - SxxEyy.en.srt`.
  - **Subtitles below their video:** a subtitle in a folder with no video of its own (`Subs`, `Subtitles`), named only by a language (`English.srt`, `2_English.srt`, `English.forced.srt`) or carrying a language tag, with no episode in its name or folders, is renamed after the single video in the nearest folder above it that holds videos and moved beside it (`Movie Name (2010).en.srt`). If that folder holds several videos, or the video was not renamed, the subtitle is left and reported as no match. With `-F` they stay in their folder and follow the ordinary rules.
  - **Two tracks of one language:** the one with more lines containing `[` or `]` (sound descriptions) becomes `.en.cc.srt` and the other `.en.srt`. With equal counts the first in byte-order sort of the names is the plain one. The track number is ignored. A third or later track is skipped.
- **Title casing:** Title Case small words (`a an and but by for in nor of on or the to at`) inside movie, series and episode titles and extra names are lowercased in file and folder names (`Title In Name` becomes `Title in Name`). The first and last word, a word after a colon or dash, and all-caps words are left alone, and nothing is capitalized.

Skipped and logged rather than guessed: an unrecognized subtitle language or modifier, ranged or multi-episode numbering (`S01E01-E02`, `S01E01E02`), a movie name with no year, and a rename target that already exists (unless `-f`, which asks for a typed `yes` before overwriting). The script refuses to run as root, so the folders and logs it creates belong to the library's owner. The script's header comment has the full name-parsing rules and known limitations; `-h` has usage.

`rename.sh -x` is the attention exit: it exits 2 when nothing failed but at least one file was skipped, left unmatched or (dry run) would be deleted, so a caller can tell a clean run from one that needs a person. Without `-x` those files do not change the exit status.

## `ingest.sh`

Moves finished downloads from the completed-downloads directory into Plex naming and then to the holding directory, and stops for a person only when something needs a decision. It takes `<source_dir> <holding_dir>`; `media.sh ingest` passes `$DOWNLOADS_INPUT_DIR` and `$UNENCODED_DIR`. Options: `-n` (dry run), `-w SECONDS` (settle window, default 60, `0` skips the check) and `-O DIR` (operational directory).

- **Settle check.** `tree_signature` hashes the size and modification time of every file under the source. It is taken, the script waits the settle window, and it is taken again; a difference ends the run with exit 0 and the next run retries. The hash ignores names, so it is also compared after the rename: a different value means something arrived or changed during the rename, and the move waits for the next run.
- **Preview.** `rename.sh -n -x` runs on the whole directory. Exit 2 (a skipped, unmatched or to-be-deleted file) or 1 stops the run before any change; the preview output is saved as the review file.
- **Rename.** `rename.sh -x` runs with no input attached. A subtitle-deletion prompt reads nothing, which `rename.sh` treats as "no", so the file stays and the run reports it. Any non-zero exit stops the run before the move.
- **Move.** Each top-level entry that holds a video (by `video_exts.sh`) moves whole to the holding directory with `mv -nT`. An entry with no video stays and is reported as held. An entry whose name already exists in the holding directory stays and is reported as a collision; a directory is never merged, since `mv` would nest it. An entry that vanishes between the listing and the move is a failure.

A real run writes three files under `OPDIR/Logs`: `Ingest.log` (one line per move, hold, collision and failure), `Ingest_review.txt` (what needs a person, rewritten only when its content changes and removed when nothing needs review) and `Ingest_state` (the exit code and a hash of the source and holding directories after a non-zero run). A run that finds both directories exactly as the last non-zero run left them repeats that exit code at once, with no wait, rename or log line; renaming a file, or adding or removing a name in either directory, starts the run over.

Exit codes: `0` nothing to do, not settled yet, or every entry moved; `1` a failed rename or move, or bad usage; `2` something needs a person. It refuses to run as root and needs bash 4.4+ (`mapfile -d`), GNU `find`, `flock`, `sha256sum` and `realpath`.

### Known limitations

- An entry that arrives between the settle check and the preview is renamed with the rest. The change is detected after the rename and the move is deferred, but the rename has already happened.
- When the source and holding directories are on different filesystems, `mv` copies and then deletes. An interrupted copy leaves a partial name at the target, which the next run reports as a collision instead of overwriting.

### Timer units

`install_units.sh` writes `media_<stage>.service` and `media_<stage>.timer` under `~/.config/systemd/user`, where `-s` picks the stage (`ingest` by default, or `archive`). The service runs `<scripts directory>/media.sh <stage>` once (`Type=oneshot`). The timer starts it 2 minutes after the user manager starts (`OnStartupSec`) and `-i` minutes (default 5) after each run ends (`OnUnitInactiveSec`), so runs never overlap. An existing unit file is left in place unless `-f` is given. It prints the `systemctl` commands that enable the timer and does not run them. It refuses a scripts path containing whitespace, `%`, `$`, a quote or a backslash, since systemd would misread it in `ExecStart`.

## `release.sh`

Moves entries from the holding directory to the encoder's input directory. It takes `-S <holding_dir> -D <input_dir>`, then options, then item names; `media.sh release` supplies the directories and passes everything after `release` through.

- With no item and no `-a`, it lists the held entries and moves nothing.
- An item is a bare entry name. A path, `.`, `..` or a name not held is reported as no match.
- `-a` releases every entry. `-a` with item names is refused.
- A name that already exists in the input directory is skipped and logged, never overwritten or merged.
- `-n` previews the moves without a lock or a log. A real run logs to `OPDIR/Logs/Release_<date>_<time>.txt`.

Exit codes: `1` when a move fails or the lock is held; skipped and unmatched items do not change the status. It is safe while an encode runs, because `encode.sh` lists its input files once at the start, so a released entry waits for the next encode. It refuses to run as root.

## `archive.sh`

Moves encoded files from the local archive directory to the NAS archive directory. It takes `-m <mount_point> <source_dir> <nas_archive_dir>`; `media.sh archive` passes `$NAS_MOUNT`, `$ARCHIVE_DIR` and `$NAS_ARCHIVE_DIR`. Options: `-n` (dry run), `-w SECONDS` (settle window, default 60, `0` skips the check), `-s` (verify by size only) and `-O DIR` (operational directory).

- **Categories.** Each top-level directory of the source is a category and must already exist on the NAS; the script never creates one. Files under it keep their relative path and merge into the show and movie folders already there, at file level. A top-level entry that is not a category folder on the NAS (a loose file, or a title folder not yet placed in a category) stays in the source and is reported. `encode.sh -r` mirrors the `$INPUT_DIR` layout into `$ARCHIVE_DIR`, and `release.sh` moves entries to the root of `$INPUT_DIR`, so an entry reaches `$ARCHIVE_DIR` under a category only when it was placed in one before the encode.
- **Mount check.** `-m` must be a mount point and the NAS directory must lie under it, or the run ends with exit 1 before any work, so an unmounted share is never mistaken for an empty one.
- **Settle.** A file modified within the last `-w` seconds is skipped and listed as waiting; the next run retries it. `encode.sh -M` writes straight to the final name in `$ARCHIVE_DIR`, so a copy in progress has a recent modification time.
- **Move.** Per file: copy to a hidden `.<name>.tmp` beside the destination, compare size and contents (`cmp`; size only with `-s`), confirm the source's size and modification time did not change during the copy, rename into place with `mv -n`, then delete the source. A failed step removes the partial copy and keeps the source. Folders emptied by the moves are removed, innermost first; the category folders stay.
- **Collisions.** A destination that already exists is never overwritten. The source stays and is reported as a collision, with the size comparison in the message.

A real run writes `OPDIR/Logs/Archive_<date>_<time>.txt`. Exit codes: `0` nothing to do, files still waiting, or every file moved; `1` a failed copy, verification or delete, a held lock, an unmounted share or bad usage; `2` a collision, or a top-level entry that is not a category folder on the NAS. It refuses to run as root and needs bash 4.0+, `flock`, `mountpoint`, `sha256sum`, `realpath` and `cmp`.

Known limitation: a writer that stalls for longer than the settle window leaves a partial file that looks finished. The size and modification-time recheck catches a file that grows during the copy, not one that has stopped growing short of its full size.

Known limitation: a file whose name the share rejects fails the copy, stays in the source, and is reported again by every run. The mount options decide which names are rejected (`mapposix` and `mapchars` in `mount.cifs(8)`, passed with `setup_smb_mount.sh -o`); the default translates none of the reserved characters.

## Subtitle tag stripping (`strip_subtitle_tags.py`)

Some subtitle files carry leftover ASS/SSA override tags (for example `{\an8}`, a positioning tag) as literal text, from an ASS→SRT conversion that kept the tags. Most players, including Plex on TV clients, don't parse the tag and instead display it as on-screen text. `strip_subtitle_tags.py strip SRC DEST` strips any `{\...}` bracketed override sequence (structural match on a single line, not a tag-name keyword list) from a plain-text subtitle file, writing the result to a scratch copy — the original file is never modified. `encode.sh` calls it through `strip_sidecar_sub()` and owns the scratch directory, which is removed on exit. `strip_subtitle_tags.py has SRC` exits 0 when the file contains a tag, which is how `encode.sh` checks an extracted embedded track before deciding to strip it.

This is sidecar-file logic specifically (a real file already on disk); an *embedded* subtitle stream can't be edited in place the same way, and no script here repairs one.

Genuine `ass`/`ssa` tracks are never run through this pipeline anywhere in this project: their override tags are real positioning, correctly rendered by an ASS-capable player, not a conversion artifact to remove.

## Plex labels (Age and Target)

Every item in the Plex library gets exactly one Age label and one Target label. Target comes from a recorded MAL demographic whenever one exists, then from the source work's demographic. Only when neither exists is it inferred, first from the source work's magazine, then from genre, and those rows are marked in `Target Basis`.

| Label | Values |
|---|---|
| `Age-` | `Kids`, `Teen`, `Adult` |
| `Target-` | `Male`, `Female`, `Unspecified` |

`Unspecified` means no source records a demographic. It does not mean a mixed audience: MyAnimeList has no both-genders value.

### Stages

| Stage | Script | Reads | Writes | Needs |
|---|---|---|---|---|
| 1 | `plex_labels.sh sync` | the Plex library (or `--dir PATH`) | `data/plex_folders.csv` | `PLEX_URL`, `PLEX_TOKEN`; optional `PLEX_LIBRARY` |
| 2 | `plex_labels.sh get` | `data/plex_folders.csv` (and the ID map, downloaded) | `data/plex_labels.csv` | `MAL_CLIENT_ID` for `--source mal-api`; `TMDB_API_KEY` unless `--no-tmdb` |
| 3 | `plex_labels.sh apply` | `data/plex_labels.csv` | labels in Plex | `PLEX_URL`, `PLEX_TOKEN`; optional `PLEX_LIBRARY` |

`plex_labels.sh [all] [-n|--dry-run] [--check-source-route] [-h]` runs all three, with `--source mal-api --force` for stage 2. It checks the environment variables before stage 1 and stops at the first of stages 1 and 2 that exits non-zero (`STOPPED` for exit 2, `FAILED` otherwise), so nothing is applied to Plex from a partial result. Exit 2 from stage 3 means the labels were applied but some folders were not found in Plex or some rows were skipped; the script prints a `NOTE`, finishes with `Done, with items needing attention` and exits 2. With `--dry-run` every stage runs in dry-run and `plex_labels.csv` must already exist from an earlier run. `plex_labels.sh sync|get|apply [ARGS...]` runs one stage and passes ARGS through to its Python script, so `./plex_labels.sh get --assess-genres` runs stage 2 with that flag, and each Python script prints its usage with `-h`.

Credentials come from the environment and are never written to a file or log. `PLEX_URL` is the server's address with scheme and port, for example `http://192.168.1.20:32400`. If the server's "Secure connections" setting is Required, plain `http://` is rejected.

### Data files (in `data/`, local and not committed)

Two files, both CSV, both generated:

- **`plex_folders.csv`:** a header row, then one row per Plex folder in the form `Title (Year)`. Stage 1 creates and maintains it. The first column is `Plex Folder`; five more are filled from Plex's own record of each show and rewritten on every sync: `Plex Title`, `Plex Original Title`, `Plex TMDB ID`, `Plex TVDB ID`, `Plex IMDB ID`. Any other column is kept as is and ignored.
- **`plex_labels.csv`:** the output of stage 2 and the input of stage 3, with one row per folder.

There are no override files. Stage 2 identifies each show from the IDs Plex already holds, so a wrong or missing match is corrected in Plex (Fix Match), and the next sync carries the new IDs into `plex_folders.csv`. A folder whose IDs are not in the ID map or on TMDB is listed as `UNRESOLVED` with the reason at the end of the stage 2 run.

### Stage 1: Sync the folder list

`plex_labels.sh sync` lists the folder of every show in the Plex show libraries (the one named by `PLEX_LIBRARY`, or all of them) and makes `data/plex_folders.csv` match. It creates the file on the first run. Afterwards it adds folders new to the library and removes folders no longer in it, keeps the rows of folders that are still there unchanged (including any extra columns) and sorts by folder name ignoring case. It also rewrites the Plex columns from each show's metadata: its title, original title and the first TMDB, TVDB and IMDB ID among its `Guid` entries (or, on the legacy TheTVDB agent, its `guid`). The library listing is asked for IDs with `includeGuids`; a show's own metadata is requested only when the listing lacks its folder or IDs. Correcting a match in Plex therefore reaches the label stage on the next sync. It asks Plex over its API, so it needs no mounted share; `--dir PATH` has no Plex metadata, so it leaves the Plex columns as they are, and lists the sub-directories of a path (for example a mounted NAS share) instead, skipping names that start with `.`, `@` or `#` (hidden entries, Synology's `@eaDir` and `#recycle`). Movie libraries are not listed.

Nothing is written when the listing is empty or would remove more than half of the existing rows, since that usually means the wrong library, a wrong path or an unmounted share; `--force` overrides the second check. `--dry-run` logs every `ADD` and `REMOVE` and writes nothing.

### Stage 2: Age and Target from MyAnimeList, then TMDB

Every folder goes to MAL first. A folder with no MAL match is then looked up on TMDB, and a folder neither knows is listed at the end of the run with the reason, so no separate stage or file is needed for Western shows. MAL rules first, TMDB rules after them.

**ID map.** MAL does not accept TVDB, TMDB or IMDB IDs, so the stage downloads the community list [Fribb/anime-lists](https://github.com/Fribb/anime-lists) (`anime-list-full.json`, `master` branch), which maps them to MAL IDs, and saves a reduced copy as `get_plex_labels_idmap.json` next to the scripts. It is downloaded again when the copy is older than 7 days (`--refresh-idmap` forces it, `--no-idmap` skips it). If the download fails, a saved copy is used however old it is; with none, the log says so and every folder is found by title search. Corrections to that list are made in its source projects, not here.

#### MAL

| Target | From |
|---|---|
| Male | MAL demographic Shounen or Seinen |
| Female | MAL demographic Shoujo or Josei |
| Unspecified | none, or Kids |
| Male or Female (inferred, magazine) | no demographic anywhere; the source work's magazines that appear in `MAGAZINE_TARGETS` agree (taken from Wikipedia's list of manga magazines) |
| Male (inferred) | no demographic anywhere, genre Harem |
| Female (inferred) | no demographic anywhere, genre Reverse Harem or Boys Love |

Digital platforms and magazines Wikipedia gives no demographic for decide nothing, and magazines never change Age. Genre tags that disagree (Harem with Reverse Harem), Girls Love and all other genres leave Unspecified. Inferred rows are not published demographics; filter on `Target Basis`.

**Finding the MAL entry.** First by Plex's IDs: the TVDB, then TMDB (TV), then IMDB ID is looked up in the ID map. One MAL entry is taken as is (`Match Check` `Plex ID`). Several, since one TVDB series can span several MAL entries, are decided by the folder year: the entries starting that year, and among them the best title match; failing that, entries one year off, marked `Review`. Otherwise by title search: the folder's title, then Plex's title and original title, accepted by the existing title-and-year scoring.

| Age | From |
|---|---|
| Kids | MAL demographic Kids |
| Teen | demographic Shounen or Shoujo, or rating PG-13 |
| Adult | demographic Seinen or Josei, or rating R, R+ or Rx |
| Kids | rating G or PG, when no demographic or rating gives a higher age |

When both a demographic and a rating give an age, the higher wins. Kids as a demographic wins outright.

A folder with no MAL match on either source, an API failure, or no rating gets `Undefined` for both, and the apply stage skips it. `Match Check` in the output is `Plex ID` (named by Plex's IDs), `OK` (title and year agree), or `Review` (only one agreed, or the year was one off; check the MAL page).

**Source works.** MAL's API does not say which manga or novel an anime adapts, so for an anime with no demographic of its own the script asks AniList (`graphql.anilist.co`, no key needed; requests are spaced 2 seconds apart) for the work's `SOURCE` relation, then reads that work's demographic from MAL's manga endpoint. A light novel (MAL `media_type` `light_novel` or `novel`) with no demographic of its own contributes the demographic of its comic adaptation (MAL relation `adaptation`); `Source Basis` shows both links. Source works that disagree on gender, no source work, or no demographic anywhere leave the Target Unspecified. This needs `--source mal-api` and can be turned off with `--no-source-works`.

**Checking the route.** `--check-source-route` traces anime that already have a demographic through their source work and logs `CONTROL MATCH` or `CONTROL DIFFER` for each, plus an agreement count. It changes no output. Run it to test whether the source-work route agrees with MAL before relying on it. Agreement compares Male against Female, so Shounen against Seinen counts as a match.

**Output columns:** `Plex Folder, Age, Target, Basis, Match Check, MAL Title, MAL Demographic, MAL Rating, Source Demographic, Source Basis, Target Basis, Source Magazine, Source`. Source Demographic and Source Basis are filled only when the anime has no demographic of its own. Target Basis reads `Magazine: <names>` or `Genre: <tags>` when Target was inferred. `Source Magazine` lists the source work's serialization names and changes nothing. `Source` is `MAL`, `TMDB`, or `None` when neither resolved the folder; for a `TMDB` row, `Basis` is the TMDB page and `MAL Rating` holds the US rating.

**Cache.** Finished lookups are cached in one file, `get_plex_labels_cache.json` next to the scripts, with a section per source (`jikan`, `mal-api`, `tmdb`), so a re-run makes no requests for them. The ID map has its own file. When the cache file does not exist, the old `get_anime_labels_cache*.json` and `get_western_labels_cache.json` beside it are imported into it once and left untouched, so no lookup is repeated after the merge. A cached source-work result from an older query version is looked up again. Delete the file to refresh everything.

#### TMDB (folders MAL has no entry for)

Resolved in this order: Plex's TMDB ID, used directly (`TV rating (Plex ID)`); Plex's TVDB ID, then IMDB ID, through TMDB's find-by-external-ID endpoint, taking a single TV result (`TV rating (Plex ID)`); then a title search by the folder's title, then Plex's title and original title. The show must match on name and first-air year; zero or several matches leave the row Undefined with the reason in `Match Check`. A row found by title search is marked `TV rating (title search)`, so it can be reviewed. Age comes from the US TV Parental Guidelines rating on TMDB: TV-Y, TV-Y7, TV-Y7-FV and TV-G are Kids, TV-PG and TV-14 are Teen, TV-MA is Adult. Target is Unspecified, since US ratings name no gendered audience. A folder whose MAL lookup failed is not sent to TMDB, and a folder MAL matched is never overwritten by TMDB, even when MAL gave it no rating.

A show that resolved to a TMDB ID with a US rating is cached; misses, missing ratings and request failures are not cached and are retried on the next run. A changed Plex ID or title looks the folder up afresh. `--no-tmdb` skips TMDB and its key.

### Stage 3: Apply to Plex

Matches each CSV row to the Plex item whose folder name on disk equals `Plex Folder` (a show's folder, or a movie's folder or file name), not its title. It writes `Age-<value>` and `Target-<value>`, and removes any other `Age-` or `Target-` label on the item so each ends with exactly one of each; labels with any other prefix are never touched. Each item's current labels are read from its own metadata record, one extra request per item. After applying, it re-reads the libraries and reports any item whose labels still differ.

Without `PLEX_LIBRARY` or `--library` every show and movie library on the server is searched; a folder name found in more than one library is reported as ambiguous and skipped. A CSV folder with no matching item is reported as not found.

### Logs and exit codes

Logs go to `plex/logs/` (the `logs` directory beside `scripts/`): `get_plex_labels.log`, `apply_plex_labels.log`. Exit codes for stages 1 and 2: `0` complete, `1` aborted (outage, bad credentials, repeated failures, bad input), `2` complete but some lookups failed or rows went unmatched. A re-run retries only the failed lookups. `encode.sh` and `rename.sh` exit `0` when no file failed and `1` when any did, and `encode.sh` also exits `1` with "No video files found." when its input holds none; skipped and unmatched files do not change the status, except with `rename.sh -x`, which then exits `2`. `ingest.sh`, `release.sh` and `archive.sh` exit as described in their sections.

### Flag conventions

`-n` (or `--dry-run` on the Python tools and `plex_labels.sh`) is a dry run everywhere, and `-f` (or `--force`) is a force flag, except in `encode.sh`, where `-f` selects the output container and `-F` selects flat output; in `rename.sh` and `setup_smb_mount.sh` `-f` forces and `-F` (renamer) restricts the run to files. `encode.sh -o DIR` is the output directory and `rename.sh -O DIR` the operational directory; `ingest.sh` and `release.sh` take `-O DIR` with the same meaning. `rename.sh -x` is the attention exit. `ingest.sh -w` is the settle window. `release.sh -S` and `-D` name the holding and input directories and `-a` releases everything. `setup_smb_mount.sh -o` is extra mount options, as in `mount -o`. `archive.sh -m` is the NAS mount point it requires, `-w` its settle window and `-s` size-only verification. `install_units.sh -s` is the stage (`ingest` or `archive`), `-i` the interval in minutes and `-f` overwrites existing unit files.

### Known limitations

- Most Unspecified titles are original anime, visual-novel or game adaptations, or adaptations of novels whose MAL entries record no demographic. A title can only be filled in from a source you can cite, by correcting the match in Plex or by hand in Plex.
- The `novel` media type is accepted but has not been seen on real data; `light_novel` has.
- Stage 2 depends on AniList being reachable from the machine running it. If it is not, run with `--no-source-works`.
